# 0.1.x

> **Beta.** Everything under 0.1.x is an unfinished preview: breaking changes can
> land at any time, saved servers or local data may need to be wiped between
> builds, and anything documented here can change before a stable release.

## 0.1.0 — 2026-10-01

Initial release of the Naigi mobile app. The app is a Capacitor shell around the shared frontend (`naigi-frontend` 0.2.0), so all user interface, end-to-end encryption, and voice/video come from the same audited code as the web and desktop clients.

### Added

- Capacitor project for Android, with the iOS platform ready to be generated on macOS.
- A sync pipeline that builds the shared frontend's `mobile` target into `www/` and injects the native bridge into every page.
- `window.naigiMobile`, a dependency-free bridge for the bundled pages.
- A server picker, shown before anything else, for choosing a self-hosted server. It validates the address, confirms it answers as Naigi, and remembers up to ten servers with the most recent first. Verification reports why it failed (unknown host, untrusted certificate, unreachable, or not a Naigi server) instead of one generic message.
- A native transport that sends the bundled pages' `/v1` calls to the selected server, carrying encrypted attachment bytes in both directions and forwarding session cookies through the platform cookie store. The page waits for the transport to become available instead of silently falling back to broken local requests.
- A way back to the picker from sign-in and registration, for when the wrong server was chosen.
- A permission bridge that reports and requests runtime permissions only when a feature needs them, and flags permanent refusals so the interface can direct the user to system settings.
- A local preview server (`npm run preview`) for reviewing the mobile interface at phone size.

### Security

- Nothing is requested at launch. Sign-in and reading conversations work with no permissions granted.
- Microphone, camera, Bluetooth, and notification permissions are declared in the manifest and requested in context.
- No broad storage permissions: attachments are chosen through the system pickers and cached in app-scoped storage.
- Cleartext traffic is disabled and backup is off, so servers must be reachable over HTTPS and app data is not exported. User-installed CAs (for example a private Caddy CA) are trusted so self-hosted servers work.
- Server addresses must be `https` origins without credentials or paths, are limited to ten, and the native transport refuses any request that does not match the selected server.
- Removing a saved server leaves keys, messages, and drafts on the device untouched.

### Known limitations

- Local names such as `.home.arpa` only resolve if the phone actually uses the local DNS server. If another DNS server in the list answers first, lookups fail; point the Wi-Fi connection at the local DNS server in that case.
- The native request transport is covered by JVM tests against a local HTTP server and browser-driven checks, but the full sign-in flow on a device is still being validated.
- Push notifications need `google-services.json` and APNs configuration.
- No code signing, store metadata, or release automation.
